# 图表视觉语言

## 先选表达范式

| 信息关系 | 优先范式 | 重点 |
|---|---|---|
| 有明确执行顺序 | 流程图 / 控制框图 | 主链、分支、反馈 |
| 模块分层与依赖 | 架构图 / 分层框图 | 边界、职责、接口 |
| 时间先后与里程碑 | 时间线 / 阶段图 | 时间刻度、阶段变化 |
| 多项并列或递进 | 列表图 / 步骤图 / Chevron | 顺序、层次、完成度 |
| 中心主题向外发散 | 思维导图 / 概念图 | 分类、关联、层级 |
| 集合、占比或循环 | 维恩图 / 环形图 / 饼图 | 数量关系或重叠 |
| 专业设备与拓扑 | 网络图 / 电气图 / 平面图 | 标准符号、端口、连接 |

不要把上述范式统一画成圆角矩形串联；也不要为了形状多样，把工程控制框图套成流程图。形状相同但职责相同是合理的。

## 形状语义

| 语义 | 图形 |
|---|---|
| 开始、结束、稳定状态 | 椭圆或胶囊形 |
| 过程、模块、任务 | 矩形或圆角矩形 |
| 条件、判断、分流 | 菱形 |
| 输入、输出、外部命令 | 平行四边形 |
| 队列、缓存、持久化数据 | 圆柱体 |
| 文档、报告、清单 | 文档形 |
| 子流程、可展开模块 | 双边框子流程 |
| 阶段推进 | Chevron 箭头块 |
| 注释、限制、注意事项 | 便笺或标注符号 |
| 设备、传感器、网络、电气元件 | 对应专业原生符号 |

## 视觉通道分工

- 形状：对象种类。
- 颜色：职责域、状态或风险级别；同一职责域保持同色系。
- 实线：主流程、数据流或强依赖。
- 虚线：依图表领域约定表达辅助、异步或可选关系；控制反馈不自动等于虚线。
- 点线：关联、注释、监测或弱依赖。
- 线宽：重要程度；主链略粗，辅助线较细。
- 分组容器：模块边界、线程域、硬件/软件域或泳道。

每个视觉通道尽量只表达一个维度，避免“红色既表示错误，又表示硬件，还表示关键链路”。

## 层级与密度

- 总览图：5～9 个一级节点，每个节点 1 个标题加最多 2 行短说明。
- 详细图：只展开一个一级节点，允许状态、参数和异常分支。
- 重要对象尺寸更大或位于视觉中心；辅助任务放在侧面或底部。
- 主链默认从左到右或从上到下，同阶段对齐；反馈走外围独立通道。多路汇入先分配端口，只有语义上确实存在接口或汇聚点时才增加节点。
- 图题说明“这张图回答什么问题”，副标题可说明主循环、中断、硬件等职责分工。

## 参考图提取清单

看到参考图后依次记录：

1. 画布方向与主链方向。
2. 一级节点数量、位置与宽高比例。
3. 是否有上下分层、泳道、容器或外围反馈。
4. 形状分别表达什么语义。
5. 实线、虚线、颜色和箭头分别表达什么关系。
6. 视觉重心和最重要的 1～2 条链路。

复刻时优先保持拓扑、层级、反馈路径和形状语法；文字可压缩，关键关系不可省略。“画得大致”只减少次要说明，不删除关键队列、中断、接口或反馈。

## 无参考图时的默认视觉方案

采用清爽的技术说明图：浅色职责彩框、协调的同色系描边、明确标题层级。默认用不同颜色区分职责，同一职责保持同色；先确定职责映射再上色。它是起点，用户参考图、品牌或专业制图约定优先；不强迫所有类型使用同一布局。

| 角色 | 建议样式 | 用途 |
|---|---|---|
| 画布 / 分组 | 白底；分组底色 `#F8FAFC` | 让内容与关系成为视觉主体 |
| 正文 / 次级文字 | `#0F172A` / `#475569` | 标题加粗，说明减轻，不降低到难读的浅灰 |
| 指令 / 输入 | `#F5F3FF` 浅紫底，`#7C3AED` 描边 | 表示外部输入或目标 |
| 控制 / 处理 | `#EFF6FF` 浅蓝底，`#2563EB` 描边 | 表示控制、计算或处理职责 |
| 反馈 / 测量 | `#F0FDFA` 浅青底，`#0F766E` | 有反馈域时使用 |
| 能量 / 执行 | `#FFF7ED` 浅橙底，`#C2410C` | 有硬件执行域时使用 |
| 说明 / 背景信息 | 白底或 `#F8FAFC`，`#CBD5E1` 描边 | 辅助文字，不代替主要职责色 |

- 色彩数量由职责类别决定，常见总览可从三至五个协调色系起步，不为压缩颜色数量合并不同职责，也不按节点轮流换色。表中职责仅为示例，其他领域按实际职责重新映射；不叠加渐变、阴影和装饰图标。
- 核心模块沿用所属职责色，通过位置、标题字重或适度加强描边突出；不要再用另一套颜色表示重要程度。图中已有明确职责标签时无需重复图例，映射不直观时增加简短图例。
- 边框约 1～1.5px，主线约 1.5～2px，辅助线约 1～1.25px。强调主要靠位置、层级和少量色彩，避免所有元素都粗边框。
- 节点标题与说明分层显示：图题 24～28px，节点标题 18～20px 加粗，说明 14～16px，边标签 14px；长说明左对齐，短标签或公式可居中。需要独立文本对象时，把它们设为节点子元素，使编辑和移动仍是一体。
- 图题直接说主题。副标题、图例、编号、底部卡片按解释需要添加，不自动凑齐一套装饰。

## 先安排阅读空间，再安排节点

- 先确定最终阅读场景。对话或屏幕总览可从约 1200～1440px 宽开始，横向构图常用 16:9 或 3:2，但内容与清晰度优先；打印按纸张与实际字号安排。
- 总览超出可读宽度时，先减少重复说明，再用真实职责分组，最后拆总览与局部详图。不要为了横排七八个完整说明框，把画布拉到必须大幅缩小才能看全。
- 对控制系统，可用“指令 / 控制器 / 驱动与被控对象”的职责区，将传感反馈放在附近的下层。控制器内部保留环路关系；硬件集成边界与功能分组要区分，不能为了布局暗示它们是独立芯片。
- 对多路反馈，先在草图上分配返回通道，按目标位置安排嵌套顺序；通道保持紧凑，不让返回线围出比主图更大的空白区域。
- 同一信号分支用明确连接点；不同信号不能为省空间合成一条无标识总线。无法避免的交叉使用跨线或清楚的非连接表达。
- 用对齐和邻近表达归属；只有确实表示模块、阶段或职责边界时才画容器，不在每个节点外再套一层卡片。

## 尺寸与留白

- 8px 网格作为起点：普通间距 32～48px；带标签的边按文字宽度加余量；相邻反馈通道 24～32px 起。容器内留白约 24px，标题区约 40px。它们是建议值，不为满足数字拉长画布。
- 按实际换行估算节点尺寸：宽度约为最长行字形宽度加两侧内边距，高度约为行数 × 字号 × 1.4 加上下内边距；中文每字约 1 个字号宽、英文约 0.55，仅用于初筛。
- 文字不得溢出、贴边、裁切或形成孤立单字行；空间不足先精简重复说明、重排或拆图，不用小于 14px 的文字硬塞。
- 标签避开节点、箭头、拐点与其他标签，与相邻节点尽量留至少 10px。正文不得压到容器标题区。
- 容器包含子元素是有意重叠，普通节点或标签遮挡不是；实际字形与边标签位置以渲染为准。

## 文字与连线的分工

- 节点标题回答“是什么”，一行说明回答“做什么”；边标签回答“传什么”。同一个短语不要在节点、边和图例中重复三遍。
- 入门图先用通俗短句；符号只保留理解关系必需的部分。详细公式、频率定义或长解释放在局部详图或随图说明中，不默认堆三张大便笺。
- 标签横向可读、靠近对应线段，并与箭头尖端留出空隙。优先置于线段上方；不要让白底标签大面积切断主线，也不要让文字挤到箭头上。
- 每条反馈回路只标一次关键测量量；把标签放在错开的水平段，避免多个标签集中在画布正中形成竖直文字堆。

## 渲染后的视觉验收

1. **整体阅读**：在实际展示宽度看全图。能否迅速找到入口、主链和关键反馈？是否必须放大才能读主要节点？如果如此，调整布局或分图。
2. **层级检查**：主模块比图例、注释更醒目；同级元素风格一致；辅助说明不能抢占主要视觉面积。大段空白若仅由绕线造成，应收紧通道。
3. **细节检查**：在 100% 下逐条追踪箭头，检查标签是否断成竖排、是否覆盖线或箭头，以及文本、边框和画布裁切。几何检查通过仍须看渲染。
4. **拓扑复核**：分组、简化和移位不能丢失反馈、混淆信号或改变因果方向。修正后只重验受影响布局与相关关系。

若用户评价“不好看”，先找出一至三个可见的表达问题（例如过宽、同等强调、标签拥挤），再针对它们重排；不要机械增加颜色、形状、图标或更多规则。
