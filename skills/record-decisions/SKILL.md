# 记录会话关键信息

将后续继续对话所需的关键信息固化为简洁、可检索的快照：目标、对齐结论、约束、当前状态和下一步。

- **默认写入当前项目目录**下的 `decision-log.md`（以当前工作目录为项目根），不再写入本技能所在的全局目录。
- 只有当用户明确要求“记录到全局 decision-log”“跨项目记录”或类似表达时，才使用本技能目录下的 `decision-log.md`。此时必须在条目中记录**相关目录路径**，以便后续追溯该快照对应的项目或工作目录。

其中“当前有效上下文索引”可更新，历史快照只追加。

## 触发边界

- 仅在用户明确要求记录当前会话要点（如“记录当前会话要点”“记录当前对话要点”“保存本次会话要点”）、明确要求查阅已保存会话记录，或显式调用 `$record-decisions` 时执行。
- 不因出现“决策”“结论”“选择”“记录”等词自动写入；讨论本技能本身的配置也不是一次记录请求。
- 普通总结、分析、实施任务和后续对话默认不读取、不写入此文件。

## 工作流程

1. 记录和查阅都使用当前项目目录下的 `decision-log.md`（路径为 `./decision-log.md`，相对当前工作目录）。恢复会话时先读取“当前有效上下文索引”，再读取索引中相关主题的最新历史快照及其取代关系；用户明确指定已完成主题时，再查阅对应历史。若项目尚无该文件，则新建。
2. 在用户触发记录后，从当前会话识别：目标与范围、已回答的对齐问题、已确认或暂定决定、条件与约束、当前状态与已完成结果、待处理问题、待澄清项和下一步。只记录后续会话需要复用的信息。
3. 明确区分“已确认”“暂定”“待澄清”和“仅建议”。不把推测、逐轮聊天复述、一次性细节、完整敏感内容或凭据写入记录；必要时只保留脱敏的约束或引用位置。
4. 为每个主题使用稳定的“主题 ID”（短小、唯一、后续更新不变）。读取 `decision-log.md`，按主题 ID 去重；状态推进或结论修正时追加新快照并填写“取代关系”，不要重写历史条目。
5. 追加快照后更新“当前有效上下文索引”：进行中、等待用户、受阻、暂停的主题保留一行；已完成主题从索引移除，历史仍保留。索引每个主题 ID 只能有一行，记录其最新状态、更新时间、下一步、最新快照标题和相关目录路径。
6. 按下方格式创建或更新记录。使用当天日期和时间；未知信息写“未说明”，不要臆造。
7. 若没有可记录的会话信息或目标文件无法安全写入，说明缺少的最小信息并暂停，不创建空记录。
8. 回复中说明记录或查阅的主题、状态、待办和文件路径；恢复会话时先给出这些要点，再继续任务。

## 条目格式

```markdown
## YYYY-MM-DD HH:mm — <主题>

- 主题 ID：<稳定短标识，例如 `session-memory`>
- 类型：会话快照 | 认知对齐 | 纠正 | 方向确认 | 长期约定
- 状态：进行中 | 等待用户 | 受阻 | 暂停 | 已完成
- 相关目录：<快照对应的当前工作目录或项目根路径；写入项目默认 decision-log 时可为“项目默认”>
- 目标与范围：<要解决的问题、边界与不做什么>
- 已对齐信息：<关键提问与已确认答案；无则“无”>
- 已确认决定：<确定方向、对象、取舍；无则“未说明”>
- 条件与约束：<验收、权限、风险、技术或时间约束；无则“未说明”>
- 当前状态/已完成：<已知事实、已完成步骤与结果>
- 待处理：<下一步行动、负责人或阻塞项；无则“无”>
- 待澄清：<继续前必须确认的问题；无则“无”>
- 依据：<确认来源、文件、命令或讨论结论；无则“未说明”>
- 取代关系：<被本条修正或取代的历史条目；无则“无”>
```

仅“当前有效上下文索引”可以就地更新；历史快照始终保持不变。需要修正时，追加一条说明取代关系的新记录，而非重写原记录。优先简洁、可检索和能让下一次会话立即恢复上下文，而非完整复述对话。
