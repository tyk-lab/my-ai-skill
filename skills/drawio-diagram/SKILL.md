# Draw.io Diagram

生成结构清晰、符号语义准确、可编辑且经过验证的图表。所有图表（包括思维导图和概念图）统一使用 draw.io 原生 `mxGraphModel` 格式，不使用 Mermaid、CSV 或其他绘图后端伪装目标格式。

## 手动触发规则

- 仅当用户在当前请求中明确说“使用画图技能”或“用画图技能”，或者显式调用 `$drawio-diagram` 时，才执行本技能。
- 不从任务类型、目标格式、文件扩展名、上下文或先前轮次推断触发；用户只说“画图”“做个图”“流程图”“使用 draw.io”“创建 .drawio”等均不触发本技能。
- 未满足手动触发条件时，不读取本技能的引用和脚本，不执行其流程；回到通用工作流，根据任务选择 SVG、HTML、Markdown/ASCII、绘图库或其他合适方法。
- 手动触发只对当前请求有效，后续请求必须再次明确调用。
- 用户明确要求“不使用画图技能”或指定其他实现方式时，立即退出本技能流程并遵从用户指定方式。

## 适用边界

- 手动触发后，使用本技能创建、编辑、验证、打开或导出 draw.io 图表。
- 技能触发后，小型概念图同样生成原生 `.drawio`；SVG 等格式从源文件导出，不因图小自行切换后端。用户明确指定其他实现方式时才遵从该方式。

## 核心流程

1. 提取图表目的、阅读层级、节点、关系、方向、分组、关键反馈、参考图特征和输出路径。
2. 先选表达范式，再选具体符号：流程图、分层框图、时间线、列表、概念图、网络图等不可混为同一种“方框连线图”。
3. 读取 [视觉设计规则](references/visual-language.md) 和 [draw.io 生成规范](references/drawio.md)。先确定阅读尺寸、主次层级、布局和配色，再选择内置形状或 stencil；不要边加节点边无限扩展画布。
4. 先规划主链和反馈通道，再生成文件。总览拥挤时按职责分组或分成总览与局部详图，保留关键关系；不要把所有步骤排成长条，也不要靠增大字号和间距解决所有问题。
5. 验证结构并渲染。先按实际阅读尺寸检查主线是否突出，再放大检查文字、箭头、标签和裁切；“文件合法、没有重叠”只证明可用，不代表表达清楚。

## 规则归属

- 本文件负责调用边界、流程、交付要求及验证入口。
- [visual-language.md](references/visual-language.md) 负责表达范式、形状、职责配色、字号间距、布局及视觉验收；视觉参数只在该文件维护。
- [drawio.md](references/drawio.md) 负责 XML 层级、分组坐标、连线、样式实现及结构/编辑性验证。样式片段为实现示例，视觉参数变化时同步相应示例。
- [symbol-libraries.md](references/symbol-libraries.md) 负责专业符号的发现与选用。

## draw.io 后端与符号来源

始终使用 draw.io 后端，禁止仅修改扩展名伪造格式：

1. 读取 [references/drawio.md](references/drawio.md)，直接生成 `mxGraphModel` XML 的 `.drawio` 文件；流程图、架构图、思维导图、概念图和线框图均走此路径。
2. 通用流程、架构和框图优先使用 draw.io 内置语义形状；专业网络、云、电气、平面图等图表先查询技能内置 `stencils/` 库（可用 `scripts/sync-drawio-stencils.ps1` 下载更新）获取标准符号。
3. 找不到准确符号时，用简化语义图形并保持对象类别、端口和拓扑，不用装饰性图标冒充标准符号。

符号库发现和查询命令见 [references/symbol-libraries.md](references/symbol-libraries.md)。

## 表达与编辑原则

- 保留职责彩色框，同一职责同色；主次通过标题、位置与描边表达。
- 简化只减少次要细节，保留关键关系、反馈及真实模块边界；参考图按其拓扑与视觉层级适配。
- 需整体操作的职责容器必须建立真实父子分组，装饰背景不能冒充可编辑分组。
- 结构验证与视觉验收缺一不可，不以 XML 合法或几何无重叠代替可读性和编辑性。

## 输出格式

- 只交付可编辑的 `.drawio` 源文件；用户要求导出格式时按下一条同时提供。
- 用户要求 PNG、SVG 或 PDF 时，用 drawio CLI 导出并加 `-e` 嵌入图表 XML，保留可编辑性。
- 不覆盖现有文件；仅在用户明确要求覆盖时才重写已有文件。
- 输出文件名使用能表达内容的英文小写短横线形式，路径优先采用用户指定位置。

## 交付前验证

按 [draw.io 验证流程](references/drawio.md#验证) 检查结构、分组、导出及最终路径；按 [视觉验收](references/visual-language.md#渲染后的视觉验收) 检查整体阅读、局部细节与拓扑。移动验证使用临时副本，不改变交付布局。

若环境无法渲染或打开，明确说明未完成的视觉验证；结构验证不能替代视觉验证。
